# ClickProofer

Two small Windows projects for a mouse that emits unwanted rapid repeat clicks.

1. Run [the Python recorder](clickproofer-clickdatasetextractor/recorder.py) with `python clickproofer-clickdatasetextractor/recorder.py` or double-click `clickproofer-clickdatasetextractor/run.cmd`. Python 3 with Tkinter is the only requirement. **Stop ClickProofer while measuring raw clicks.** Pick a mouse button, click in the blue area slowly while keeping your own count, enter that count, and save the JSON. The file records each press and release, Windows message times, delivery times, hold durations, and gaps. It also reports extra clicks and a tentative threshold. To inspect a saved file again: `python clickproofer-clickdatasetextractor/recorder.py --analyze path/to/sample.json`.
2. Run `powershell -ExecutionPolicy Bypass -File clickproofer-main/build.ps1` from this folder. This requires Rust, Visual Studio C++ Build Tools, and the Windows SDK. The finished app is `clickproofer-main/target/release/clickproofer.exe`. Run it, set the threshold in milliseconds, and press **Start filtering**. **Stop filtering** reverses it immediately. Closing the window hides it to the Windows notification area and keeps filtering running. Click the tray icon to reopen it, or right-click for **Open ClickProofer**, **Start/Stop filtering**, **Enable/Disable startup**, and **Exit ClickProofer**. Exit fully stops filtering and closes the app. Windows may place the icon under the notification area's hidden-icons arrow.
3. Press **Enable startup** to launch filtering automatically, hidden in the tray with no GUI flash, when *your account signs in*. **Disable startup** removes the startup entry. No administrator permission is needed. Keep the executable at the same path after enabling startup; if you move it, disable startup first and enable it from the new path. The threshold is saved per user.

The default threshold is 33 ms, calibrated from `mouse-20261028-190820.json` (14 extra presses at gaps of 0-32 ms; the next gap was 313 ms). A physical repeat whose **press** follows the previous **release** by less than the threshold is discarded, along with its release. Each mouse button is tracked separately. Intentional double-clicks faster than the chosen threshold will also be discarded; lower it if that happens. The recorder can only estimate a threshold from the total click count because it does not know which individual clicks you intended. It does not diagnose malware or determine the hardware cause. A previously saved threshold still takes precedence; set 33 in the app if it already shows another value.

Windows [services cannot directly interact with the signed-in desktop](https://learn.microsoft.com/en-us/windows/win32/services/interactive-services), so a service alone would not filter this input. ClickProofer uses a Windows low-level mouse hook in the signed-in session, and the reversible `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\ClickProofer` entry for automatic sign-in startup. The setting is not an installation of a Windows service. Windows may bypass the hook on secure desktops, and programs using raw device input may see unfiltered clicks. If Windows times out a slow hook, filtering can stop; reopen the app. Injected mouse events are ignored by the filter.

Tests: `python -m unittest discover -s clickproofer-clickdatasetextractor -v` and `cargo test` in `clickproofer-main` (or use the build script).
